# GitHub Pages deployment

Sokomind produces a static `dist/` directory and deploys it with
`.github/workflows/deploy-pages.yml`.

## One-time repository setting

Open **Settings > Pages** in the GitHub repository and choose **GitHub
Actions** as the source. The workflow creates and uses the standard
`github-pages` environment.

## Deployment flow

Every pull request, default-branch push, or manual workflow dispatch performs:

1. checkout;
2. Node setup and `npm ci`;
3. lint;
4. dependency audit;
5. unit tests, coverage gates, and production build;
6. static artifact tests;
7. Playwright and axe tests beneath the configured preview path;
8. multi-puzzle and Grand Hall solver performance gates.

If a browser job fails, its Playwright traces and screenshots are uploaded as a
seven-day diagnostic artifact.

Pull requests stop there, while non-default-branch push events skip the build
to avoid duplicating the pull-request run. Pushes and manual runs whose full
Git ref is
the repository's default branch additionally upload the Pages artifact and
deploy through the `github-pages` environment. A same-named tag cannot satisfy
this guard. The build job receives `contents: read` and the `pages: read`
permission required by `configure-pages`; Pages write and OIDC permissions
exist only on the deploy job.

Dependabot checks npm and GitHub Actions dependencies weekly.

## Path contract

`vite.config.ts` sets `base: "./"`. Scripts, styles, the favicon, and future
static media must therefore remain relative or be imported through Vite.

Use one of these patterns:

```ts
import soundUrl from "./sound.ogg";

const worker = new Worker(
  new URL("./solver.worker.ts", import.meta.url),
  { type: "module" },
);
```

For a file in `public/`, use a relative HTML path or
`import.meta.env.BASE_URL`. Do not hard-code `/assets/...`; that points at the
host root and breaks a project site mounted at `/Sokomind/`.

Puzzle and replay routes use the URL hash, so a `404.html` fallback remains
unnecessary.

## Public metadata

The canonical product URL defaults to
`https://willpatpost.github.io/Sokomind/`. GitHub Actions derives the temporary
Pages URL from repository metadata so iteration or preview repositories do not
require code changes. Set the repository variable `PUBLIC_SITE_URL` for a
custom domain or another final canonical URL. Local builds can set
`VITE_PUBLIC_SITE_URL` directly. Include the final path; the build normalizes a
missing trailing slash.

The browser harness defaults to `/Sokomind/`. Set
`SOKOMIND_PREVIEW_BASE_PATH`, and optionally `SOKOMIND_PREVIEW_HOST` or
`SOKOMIND_PREVIEW_PORT`, to exercise a different mount path without editing
configuration files.

The production build disables public source maps and ships a 1200x630 social
image. The manifest and service worker use only relative, scope-safe paths.

GitHub Pages does not let this repository set response headers. The meta CSP
therefore covers script, style, image, connection, worker, object, base, and
form sources, but it does not claim framing protection: browsers ignore
`frame-ancestors` when it is delivered through a meta element. If framing must
be prohibited in the future, deploy through a host or edge layer that can emit
an HTTP CSP or `X-Frame-Options` response header.

## Service worker and asset precaching

`public/sw.js` uses an `asset-manifest.json` file generated by Vite. The build
hashes the worker, manifest payload, HTML, and declared resources into a
deterministic cache revision and embeds that same revision in both the worker
and manifest. Installation rejects a manifest from another build before it can
activate or prune the last known-good generation. Cache names include the
encoded service-worker registration
scope, so two GitHub Pages projects on the same origin cannot prune each
other's data. Installation bypasses the HTTP cache while staging the shell,
route code, and shared dependencies; activation validates and prunes only the
current scope's older generation. Progress/Solver dialog chunks, both solver
workers, and the generated 50-board puzzle shards remain runtime-loaded and are
cached only after use. Static tests derive each cold route's eager JavaScript
dependency closure and associated styles, include the largest board shard in
Play's budget, reject board data in the Home closure, and enforce per-shard gzip
budgets.
Navigation responses never overwrite the known-good shell, so an online 404
cannot poison offline startup. Runtime writes are restricted to
manifest-declared same-scope resources and are awaited through the fetch event
lifetime. The first worker installation claims the page without forcing an
unprompted reload. For a later update, the Reload action sends `SKIP_WAITING`
to the retained waiting worker and reloads exactly once after
`controllerchange`; dismissing the notification leaves the current page and
worker untouched.

## Local production check

```sh
npm run build
npm run test:static
npm run test:browser
npm run preview:pages
```

Do not commit `dist/`. GitHub Actions builds from the committed lockfile and
uploads the artifact directly.

The repository's `.gitattributes` pins generated inputs and outputs to LF so
the exact synchronization checks behave identically on Windows and Linux.
